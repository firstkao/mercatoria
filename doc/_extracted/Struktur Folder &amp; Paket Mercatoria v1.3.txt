1. Overview — Kenapa Struktur Ini Penting?

1.1 Analogi Gampang

Bayangin bikin kue. Ada 3 hal yang harus disiapkan dulu:


Dapur — tempat masak (folder)


Alat — mixer, oven, cetakan (paket/library)


Bahan — tepung, telur, gula (database)

Dokumen ini bahas dapur (folder) dan alat (paket). Bahannya (database) udah di dokumen Skema DB.

1.2 Kenapa Laravel Pakai Struktur Folder?

Laravel itu framework. Dia punya aturan main — kalau kamu ikutin, dia bakal kerja otomatis. Contoh:


File di app/Models/ → otomatis jadi Model yang bisa connect ke DB


File di app/Http/Controllers/ → otomatis bisa handle request dari URL


File di resources/views/ → otomatis bisa jadi halaman web

Kalau kamu taruh file di tempat yang salah, Laravel gak tahu itu apa.

1.3 Yang Perlu Dipahami Pemula


IstilahArti Gampang


FolderLemari / ruangan tempat nyimpan file


File1 dokumen kode (misal: 1 file = 1 kelas PHP)


ComposerAlat beli library PHP (kayak App Store untuk kode)


NPMAlat beli library JavaScript


BladeBahasa template Laravel (HTML + PHP)


Alpine.jsBikin halaman interaktif (tombol, dropdown)


LivewireBikin halaman real-time tanpa reload (kayak React, tapi PHP)


TailwindBikin tampilan cepat pakai class (misal: bg-blue-500)


ViteAlat build CSS + JS biar cepat

13. Alur Request (Route → Controller → Service)

Contoh: User Klik "Buat Pesanan" (Checkout)

1. USER KLIK "BUAT PESANAN"
   → Browser kirim POST /checkout dengan data form
                            ↓
2. ROUTE (routes/web.php)
   Route::post('/checkout', [CheckoutController::class, 'store'])
       ->middleware(['auth', 'turnstile']);
                            ↓
3. MIDDLEWARE (app/Http/Middleware/)
   - Authenticate → cek login
   - VerifyTurnstile → cek anti-bot
   - LogUserActivity → catat aktivitas
                            ↓
4. FORM REQUEST (app/Http/Requests/Frontend/CheckoutRequest.php)
   → Validasi: platform, payment_scheme, payment_method, dll
   → Kalau gagal → redirect back + error message
                            ↓
5. CONTROLLER (app/Http/Controllers/Frontend/CheckoutController)
   public function store(CheckoutRequest $request)
   {
       $order = $this->orderService->create($request->validated());
       return redirect()->route('orders.show', $order);
   }
                            ↓
6. SERVICE (app/Services/Order/OrderService.php)
   public function create(array $data): Order
   {
       DB::beginTransaction();
       try {
           $order = Order::create([...]);
           $this->createOrderItemsAndSnapshots($order);  // [ikon: star]
           DB::commit();
           event(new OrderCreated($order));    // trigger
           return $order;
       } catch (\Exception $e) {
           DB::rollBack();
           throw $e;
       }
   }
                            ↓
7. EVENT + LISTENER
   event(new OrderCreated($order))
       ↓
   Listener:
   - SendOrderCreatedEmail → kirim email
   - SendNotificationOnOrderCreated → kirim bell
   - NotifyAdminOnNewOrder → bell admin
                            ↓
8. RESPONSE
   → redirect ke /orders/{id}
   → user lihat detail order

13.1 Kenapa Service Dipisah?

Kalau semua logic taruh di Controller, file-nya bisa jadi 500+ baris. Susah dibaca, susah di-test. Dengan Service:


Controller cuma 5–10 baris


Service berisi business logic yang reusable


Mudah di-test (unit test)


Kalau butuh dipakai di tempat lain (misal CLI command, API), tinggal panggil service

16.2 Workflow Development


Buka 2 terminal:



Terminal 1: /usr/bin/php8.5 artisan serve


Terminal 2: npm run dev






Buka browser: http://localhost:8000


Edit kode → auto reload (Vite HMR)


Kalau ubah migration → /usr/bin/php8.5 artisan migrate


Kalau ubah config → /usr/bin/php8.5 artisan config:clear
