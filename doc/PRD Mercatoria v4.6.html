1. Ringkasan Produk

Mercatoria adalah web marketplace B2C yang membantu penggemar IP Cina (game, anime, donghua, novel) membeli merchandise resmi & fanmade dari Tiongkok — tanpa harus paham Mandarin, punya akun Taobao/Weidian, atau mengurus pengiriman internasional sendiri.

Mercatoria berperan sebagai perantara + katalog terkurasi per IP, menangani pembelian, konsolidasi, dan pengiriman ke pembeli.

Platform & Infrastruktur: Web only, semi-otomatis, berjalan di atas VPS Hostinger KVM 1 (CloudPanel v2 · Nginx · PHP 8.5-FPM · Laravel 13.x · MySQL 8.0 · Redis 7). Timezone: WIB (Asia/Jakarta, GMT+7).

8.5 Smart Scoped IP Blacklist Enforcement (Anti False-Positive CGNAT) REV v4.6

  • Layer 1 — Hard Identity Lock (Email & No HP Permanen): Email dan No HP yang masuk daftar spammers (atau Blocked permanen setelah 2x gagal unblock) dikunci total pada /register dan /login dari IP mana pun.
  • Layer 2 — Scoped IP + Device Fingerprint Ban (spammer_ips): Setiap kali email/no HP yang ter-block mencoba daftar atau login, IP-nya dicatat ke spammer_ips. IP di daftar ini diblokir penuh dari mengakses pendaftaran akun baru (/register) dan hanya bisa mengakses Beranda (/). Namun, /login tetap mengizinkan autentikasi khusus jika kredensial yang dimasukkan adalah milik akun Customer sah (MVP, Ex, ONS) yang tidak ter-block (mencegah pelanggan aktif terkunci akibat berbagi IP dinamis CGNAT provider seluler Indonesia).
  • Layer 3 — Auto-Decay / TTL IP Dinamis (30 Hari): Email & No HP di spammers ter-ban selamanya (Forever Delete), sedangkan alamat IP di spammer_ips memiliki masa aktif blokir otomatis 30 hari sejak percobaan terakhir agar rotasi IP dinamis ISP tidak memblokir pengguna publik baru selamanya.
  • Bot Crawler resmi tetap bypass restriction ini.

10.1 Trigger Masuk List Spammer

10.3 Efek (Smart Scoped Ban) REV v4.6

  • Email di list → tidak bisa daftar & tidak bisa login lagi (permanen)
  • No HP di list → tidak bisa daftar & tidak bisa dipakai di profil mana pun (permanen)
  • IP di spammer_ips (TTL 30 hari sejak attempt terakhir) → hanya bisa akses Beranda (/) dan diblokir penuh dari /register, namun tetap mengizinkan /login khusus bagi akun Customer sah (MVP/Ex/ONS) yang tidak ter-block

10.4 Unblock Manual oleh Admin & Aturan Tanpa Tameng Tier REV v4.6

  • Admin dapat melakukan unblock manual (baik untuk Spammer Crush maupun Customer Blocked yang vakum > 60 hari)
  • User punya 7 hari (grace period) untuk menyelesaikan pembayaran order baru agar kembali menjadi MVP
  • Lewat 7 hari tanpa pembayaran terverifikasi → auto-block kembali
  • Setelah 2x unblock gagal → block permanen (tidak bisa di-unblock lagi)
  • Tier Badge Bukan Tameng: Kepemilikan Tier Badge (MVP Silver, MVP Gold, maupun MVP Platinum) tidak memberikan imunitas/tameng terhadap transisi ke Blocked saat vakum > 60 hari maupun batas maksimal 2x unblock

10.5 Multi-IP Ban Tracking

16.7 Total Berat di Checkout v4.4

Saat checkout, sistem hitung total berat per item:

  • Berat = varian weight_gram kalau ada, else produk weight_gram
  • Kalau dua-duanya kosong → default 0g (admin harus input berat)
  • Total berat order = sum(berat item × qty)
  • Berat per item disimpan di order_item_snapshots.weight_gram
Berat per ITEM, bukan per order. Karena ongkir internasional dihitung per kg dari total berat, tapi saat snapshot per item kita tetap simpan berat masing-masing untuk audit. Total berat order = sum semua item.

16.8 Rumus Ongkir di Checkout v4.4

Total ongkir per item = 3 komponen:

  1. Ongkir Lokal CN (per produk, dari store produk):
    • Kalau harga produk ≥ min_belanja store → gratis (Rp 0)
    • Kalau < min_belanja → (harga_rmb × ongkir_rmb) / min_belanja × rate
    • Kalau store ongkir_rmb = 0 → gratis
  2. Ongkir CN-BTM (per item) = berat_kg × ongkir_cn_btm_per_kg
  3. Ongkir BTM-JKT (per item) = berat_kg × ongkir_btm_jkt_per_kg

Total ongkir = sum ketiga komponen per item. Detail rumus lengkap: Section 20.

20.3 Rumus Ongkir Lokal CN (per produk) v4.4

Interpretasi: Customer bayar langsung (bukan disubsidi toko).

Cek harga produk (RMB):
├── Kalau store.ongkir_rmb = 0 → GRATIS
├── Kalau harga_produk ≥ store.min_belanja_rmb → GRATIS
└── Selain itu → HITUNG:

    ongkir_lokal_rmb = (harga_produk × store.ongkir_rmb) / store.min_belanja_rmb
    ongkir_lokal_idr = ongkir_lokal_rmb × rate_rmb_idr

Contoh 1: Harga 58 yuan, store min 100, ongkir 7 yuan

58 < 100 → hitung
ongkir_lokal_rmb = (58 × 7) / 100 = 4,06 yuan
ongkir_lokal_idr = 4,06 × 2.200 = Rp 8.932

Contoh 2: Harga 150 yuan, store min 100, ongkir 7 yuan

150 ≥ 100 → GRATIS (Rp 0)

Contoh 3: Harga apa pun, store ongkir 0 yuan

ongkir_rmb = 0 → GRATIS (Rp 0)

20.4 Rumus Ongkir Internasional (per item) v4.4

Per item:

berat_kg = berat_item_gram / 1000

ongkir_cn_btm_idr  = berat_kg × ongkir_cn_btm_per_kg  (default 25.000)
ongkir_btm_jkt_idr = berat_kg × ongkir_btm_jkt_per_kg (default 60.000)

Berat item = varian.weight_gram kalau ada, else produk.weight_gram

Contoh: Berat 500g = 0,5 kg

ongkir_cn_btm_idr  = 0,5 × 25.000 = Rp 12.500
ongkir_btm_jkt_idr = 0,5 × 60.000 = Rp 30.000

20.5 Rumus Harga Bersih per Produk / Varian (Sama di Katalog, Detail Produk, Keranjang & Checkout) REV v4.6

# 1. Gunakan harga RMB varian (jika produk bervarian) atau harga RMB produk induk (jika single)
harga_rmb_item = variant.price_rmb ?? product.price_rmb
berat_gram_item = variant.weight_gram ?? product.weight_gram

harga_idr    = harga_rmb_item × rate
ongkir_lokal = (rumus 20.3 dihitung per varian menggunakan harga_rmb_item)
ongkir_btm   = (berat_gram_item / 1000) × ongkir_cn_btm_per_kg
ongkir_jkt   = (berat_gram_item / 1000) × ongkir_btm_jkt_per_kg

# 2. Profit 11% & pembulatan CEILING 5.000 sudah termasuk di dalam Harga Bersih per item
 modal_item   = harga_idr + ongkir_lokal + ongkir_btm + ongkir_jkt
profit_item  = modal_item × 0.11
harga_bersih_item = CEILING((modal_item + profit_item) / 5000) × 5000

# 3. Diskon produk nominal (kalau ada & aktif)
harga_tayang_item = harga_bersih_item - discount_amount

Prinsip Utama: Harga yang tertera di Katalog, Detail Produk, Keranjang, dan Subtotal Item di Checkout 100% SAMA (harga_tayang_item) dan sudah termasuk profit 11%.

20.6 Rumus Total Order di Checkout (Tanpa Double Profit) REV v4.6

# 1. Subtotal item di Keranjang & Checkout (sama persis dengan harga tayang produk)
subtotal_order = sum(harga_tayang_item × qty)

# 2. Diskon Koin (maks 5% dari subtotal_order) ATAU Voucher (pilih salah satu)
diskon_order = diskon_koin_atau_voucher
subtotal_setelah_diskon = subtotal_order - diskon_order

# 3. Fee Admin Logistik Marketplace (baru tampil di Checkout)
Toco   FP = Rp 1
Toco   DP = Rp 0 (saat CO pelunasan di Toco)
Shopee FP = Rp 109
Shopee DP = 25% × sisa_pelunasan_50_persen (saat CO pelunasan di Shopee)

# 4. Fee QRIS (baru tampil di Checkout jika metode == QRIS dan tagihan >= Rp 500.000)
fee_qris = 0.0003 × tagihan (jika >= 500.000, selain itu Rp 0)

# 5. Total Tagihan Checkout (dibulatkan CEILING 5.000 jika ada pecahan dari diskon/fee)
total_checkout = CEILING((subtotal_setelah_diskon + fee_marketplace_web + fee_qris) / 5000) × 5000

47. Store Concept & Berat Produk NEW v4.4

Section baru v4.4. Store Concept adalah sistem untuk mengelola tier ongkir lokal CN per toko. Karena setiap toko dari game-game punya kebijakan ongkir berbeda (min belanja gratis, ongkir flat, gratis selalu). Ditambah Berat Produk untuk hitung ongkir internasional per kg.

47.1 Tujuan

  • Admin bisa CRUD toko/tier ongkir lokal CN tanpa edit kode
  • Setiap produk terhubung ke toko (default dari game, bisa override untuk case collab)
  • Setiap produk punya berat (gram), bisa override di level varian
  • Sistem hitung otomatis 3 jenis ongkir (lokal CN, CN-BTM, BTM-JKT)
  • Snapshot simpan breakdown ongkir untuk audit trail

47.2 Konsep Dasar

Apa itu Store?

Store = representasi "toko" tempat kita beli produk. Bisa toko official game, toko collab, atau fanmade studio. Setiap toko punya kebijakan ongkir lokal CN yang berbeda.

Apa itu Tier?

Tier = level kebijakan ongkir. Istilah "tier" dan "store" di sini sama saja. Admin isi 3 field:

  • name — nama toko/tier (mis. "Official HoYoverse", "Toko Baju Collab")
  • min_belanja_rmb — minimum belanja (RMB) untuk gratis ongkir lokal
  • ongkir_rmb — ongkir lokal CN (RMB). Set 0 = gratis selalu.

Kenapa Store Terpisah dari Game?

Karena case collab: Game A collab sama Toko Baju B → tier-nya pakai tier toko B, bukan tier game A. Store berdiri sendiri, produk yang pilih store mana.

47.5 Rumus Ongkir Lokal CN

Interpretasi: Customer bayar langsung (bukan disubsidi toko).

Logic Per Varian / Produk REV v4.6

Input:
- harga_produk_rmb = variant.price_rmb ?? produk.price_rmb (Admin wajib input RMB per varian, bukan IDR)
- store = produk.store (fallback: produk.games.default_store)
- min_belanja = store.min_belanja_rmb
- ongkir_store = store.ongkir_rmb
- rate = setting('rate_rmb_idr')

Logic:
├── Kalau ongkir_store = 0
│   → ongkir_lokal = Rp 0 (gratis selalu)
│
├── Kalau min_belanja = 0
│   → ongkir_lokal = Rp 0 (biar gak divide by zero)
│
├── Kalau harga_produk ≥ min_belanja
│   → ongkir_lokal = Rp 0 (gratis karena capai minimum)
│
└── Selain itu
    → ongkir_lokal_rmb = (harga_produk × ongkir_store) / min_belanja
    → ongkir_lokal_idr = ongkir_lokal_rmb × rate

47.7 Rumus Total Harga (Full — Konsisten Produk, Keranjang & Checkout) REV v4.6

harga_idr           = harga_rmb_item × rate

profit_item         = modal_item × 0.11

47.14 Catatan Strategi

Rumus ongkir lokal CN = customer bayar langsung. Bukan disubsidi toko.
  • Alasan: kalau disubsidi, harga produk melonjak jauh, customer kabur. Contoh: produk 20 yuan + ongkir 7 yuan (subsidi penuh) = harga naik 35%.
  • Trade-off: admin rugi dikit karena ongkir sebenarnya lebih mahal dari yang dibayar customer. Tapi ini strategi acquire customer di awal.
  • Rencana: nanti kalau user base stabil, bisa revisi rumus. Snapshot freeze di order lama, jadi gak akan ganggu customer lama.

48. Migrasi User Lama NEW v4.5

Section baru v4.5. Migrasi user dari sistem lama (WooCommerce) ke Mercatoria. Karena password WooCommerce pakai hash WordPress (`$P$`), tidak bisa langsung dipakai. User wajib reset password dulu, lalu verifikasi email, lalu lengkapi profil.

48.1 Tujuan

  • Memindahkan data user lama dari WooCommerce ke Mercatoria
  • User lama tetap punya akun dengan email + HP yang sama
  • User set password sendiri (aman, user pilih sendiri)
  • Data order lama tetap tersimpan sebagai snapshot

48.2 Urutan Migrasi (WAJIB)

Urutan fix: Produk → Customer → Order. Jangan dibalik.
  1. Inject Produk → /office/products/create
  2. Inject Customer → /office/users/create (form cuma: nama, email, HP, alamat)
  3. Inject Order Lama → /office/orders/create (pilih produk, qty, harga, tanggal order)

48.4 Flow Setelah Inject

Fase 1 — Aktivasi User

  1. Admin inject user (password kosong)
  2. Admin kasih tahu user via WA/sosmed: "Akun kamu siap. Login dengan 'Lupa Password'."
  3. User buka /login → klik "Lupa Password?"
  4. Input email → sistem kirim link reset password (pakai template reset_password yang sudah ada)
  5. User klik link → set password baru (min 8 char)
  6. Auto-login → redirect ke dashboard

Fase 2 — Verifikasi Email (Soft Mode)

  1. User login → dashboard muncul banner kuning:
    "⚠️ Verifikasi email dulu biar bisa order. [ Verifikasi Sekarang ]"
  2. User bisa jelajah katalog, lihat produk, add to cart
  3. Kalau klik "Buat Pesanan" → redirect ke /verify-email
  4. Klik "Verifikasi Sekarang" → kirim email verifikasi
  5. User klik link verifikasi → email_verified_at = now()
  6. Banner hilang

Fase 3 — Lengkapi Profil (Wajib)

  1. Setelah verif → form "Lengkapi Profil"
  2. Field wajib: Tanggal Lahir (locked, 1x set seumur hidup)
  3. Setelah diisi → bisa order normal
  4. Kalau belum verified atau belum isi Tanggal Lahir → tombol "Buat Pesanan" maupun aksi "Konfirmasi Pembayaran" (jika ada tanggungan order migrasi) disabled dan otomatis diarahkan untuk menyelesaikan verifikasi email & lengkapi profil terlebih dahulu
Kenapa tgl lahir wajib? Untuk kalkulasi umur + bonus ulang tahun. Karena locked 1x, admin tidak bisa koreksi kalau salah — user harus isi sendiri dengan benar.
