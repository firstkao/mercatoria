Story EPIC-04-23: Store CRUD (List, Create, Edit, Delete) NEW

As an admin, I want CRUD store untuk tier ongkir lokal CN, so that gak perlu edit kode tiap ada toko baru.

Acceptance Criteria:

  • Halaman list: /office/stores — tabel dengan kolom Nama, Min Belanja, Ongkir, Jumlah Produk, Aksi
  • Form create: /office/stores/create — field Nama, Min Belanja (RMB), Ongkir (RMB)
  • Form edit: /office/stores/{id}/edit — plus section "Penggunaan Store" (info jumlah game & produk)

  • Ongkir = 0 → tampil "Gratis" (badge hijau)

5. EPIC-06: Story Baru — Shipping Calculator & Snapshot NEW

EPIC-06 Update — Order & Payment

Tujuan: Shipping Calculator (rumus baru), Update Snapshot (simpan breakdown), Detail Order Admin (breakdown collapsible).

Total Baru: 3 Story · 8 Task · 16 SP

Dependency: EPIC-06 existing, EPIC-04-23 (Store), EPIC-04-26 (Berat)

Sprint: Sprint 5, 8

Story EPIC-06-30: ShippingCalculatorService (Rumus Baru) NEW

As a system, I want hitung ongkir 3 jenis otomatis, so that total harga akurat.

Acceptance Criteria:

  • Service ShippingCalculatorService dengan method:
    • calculateLocalCn(Product) → ongkir lokal CN (Rp)
    • calculateCnBtm(int weightGram) → ongkir CN-BTM (Rp)
    • calculateBtmJkt(int weightGram) → ongkir BTM-JKT (Rp)
    • calculateItemShipping(Product, ?Variant) → array breakdown lengkap
  • Logic lokal CN:
    • Store ongkir = 0 → gratis
    • Store min = 0 → gratis
    • Harga ≥ min → gratis
    • Selain itu → (harga × ongkir) / min × rate
  • Logic internasional: berat_kg × rate_per_kg (dari settings)
  • Berat efektif = varian.weight_gram ?? produk.weight_gram ?? 0
  • Return array: weight_gram, store_name, 3 komponen ongkir, total

Tasks (8 SP):

  • [BE] Service class + 4 method
  • [BE] Logic lokal CN (4 cabang)
  • [BE] Logic internasional per kg
  • [BE] Method effectiveWeight() di Product & ProductVariant
  • [BE] Unit test semua cabang logic
  • [QA] Test case: harga 58 → 8.932; harga 150 → 0; store gratis → 0
  • [QA] Test case: berat 500g → CN-BTM 12.500, BTM-JKT 30.000
  • [QA] Test fallback varian null → pakai produk

Story EPIC-06-31: Update Snapshot simpan Breakdown Ongkir NEW

As a system, I want snapshot simpan breakdown ongkir, so that audit trail lengkap.

Acceptance Criteria:

  • Update OrderItemSnapshotService::createForOrderItem()
  • Panggil ShippingCalculatorService untuk hitung breakdown
  • Simpan 6 field baru di snapshot:
    • weight_gram
    • store_name
    • ongkir_lokal_cn_idr
    • ongkir_cn_btm_idr
    • ongkir_btm_jkt_idr
    • ongkir_total_idr
  • Test: checkout → buka detail order admin → breakdown tampil
  • Test: ubah store/berat produk setelah order → snapshot gak berubah (freeze)

Tasks (5 SP):

  • [BE] Inject ShippingCalculatorService ke constructor
  • [BE] Update method createForOrderItem() dengan breakdown
  • [BE] Simpan 6 field baru ke order_item_snapshots
  • [QA] Test checkout end-to-end
  • [QA] Test freeze: ubah produk setelah order → snapshot gak berubah

Story EPIC-06-32: Detail Order Admin — Breakdown Ongkir Collapsible NEW

As an admin, I want lihat breakdown ongkir per item, so that bisa audit kalau ada komplain.

Acceptance Criteria:

  • Section "📦 Detail Ongkir" di bawah info item (per item)
